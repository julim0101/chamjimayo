# 참지마요 (ChamJiMayo)

> 텍스트 마이닝 · 노동법 RAG를 활용한 **직장 내 괴롭힘 입증 지원 서비스**
> 제8회 K-디지털 트레이닝 해커톤 · 팀 **참교육스쿨**

---

## 무엇을 하는가

카카오톡 대화 내보내기(`.txt`)를 올리면

1. 개인정보를 **분석 전에** 자동 마스킹하고
2. 대화를 **근로기준법 제76조의2의 3대 성립요건**에 맞춰 정량 지표로 환산하고
3. **폐쇄형 노동법 RAG**로 근거 조항을 환각 없이 인용하여
4. 감독관용 **증거 분석 보고서** / 피해자용 **진정서 초안**을 생성합니다.

**하지 않는 것:** 괴롭힘 성립 여부 판정. 그건 근로감독관·노무사·변호사의 몫입니다.
이 서비스는 판단에 필요한 자료를 법적 요건에 맞춰 정리할 뿐입니다.

```bash

# 전체 파이프라인 (ML 모델 포함, 최초 실행 시 모델 다운로드)

# 또는 경량 구성 (ML 없이 — Tier 1 지표는 동일하게 동작)

```

## 처리 흐름

```
카톡 .txt
   ↓  parser      PC판/모바일판 포맷 인식 → (발화자, 시각, 내용) 구조화
   ↓  masking     실명→가명, 연락처·주소·계좌·주민번호→유형 태그       ← 분석 전 필수
   ↓  metrics     Tier 1 정량 지표 (3요건 매핑)
   ↓  toxicity    Tier 2 독성 분류 (KcELECTRA ⊕ 어휘 사전)
   ↓  scoring     3요건 결합 · 위험도 · 조사 우선순위 · 증거 추출
   ↓  rag         폐쇄형 법령 코퍼스에서 근거 조항 검색·인용
CaseSummary → 증거 분석 보고서 / 진정서 초안
```

## 3단계 증거 등급

| 등급 | 내용 | 근거 | 점수 반영 |
|------|------|------|-----------|
| **Tier 1** 확정 지표 | 발화 독점률, 시간외 주기성, 선택적 무응답 | 수학적 연산 · 반박 불가 | ✅ |
| **Tier 2** 분류 지표 | 모욕·독성 어휘 밀도 | 모델 확률값 | ✅ |
| **Tier 3** 정황 후보 | 가스라이팅·배제·수동공격 | 맥락 추론 | ❌ **별도 큐** |

Tier 3를 점수에 섞지 않는 것이 설계의 핵심입니다.
확률적 추론을 확정 지표와 합산하면 "반박 불가능한 숫자"라는 Tier 1의 강점이 무너집니다.
대신 **별도의 '사람 검토 필요' 큐**로 감독관에게 올립니다.

## 3요건 → 지표 매핑

### 요건① 지위 또는 관계의 우위

| 지표 | 의미 |
|------|------|
| 발화 독점률 (건수·분량) | 대화를 누가 점유하는가 |
| 지시 발화 비대칭 | 지시는 한 방향으로만 흐르는가 |
| 사과·수용 표현 비대칭 | 누가 일방적으로 사과하는가 |
| 일방적 연속 발화 비율 | 상대 응답 없이 몰아붙이는가 |
| 응답 지연 격차 | 대상자만 즉시 응답해야 하는가 |

### 요건② 업무상 적정범위 초과

| 지표 | 의미 |
|------|------|
| 근무시간 외 발화 비율 | |
| 주당 시간외 지시·응답요구 | 매뉴얼상 "반복적 업무 지시 **또는 즉각적인 응답 요구**" |
| 주당 심야(22–06시)·휴일 연락 | |
| 시간외 연락 발생일 비율 | 일회성인가 지속적인가 |
| 반복 주기의 규칙성 | 간격의 변동이 작을수록 지속적 패턴 |

건수 지표는 모두 **주당 발생률**로 정규화 — 대화량·기간이 달라도 사건 간 비교가 됩니다.

### 요건③ 신체적·정신적 고통 / 근무환경 악화

| 지표 | 의미 |
|------|------|
| 모욕·독성 발화 밀도 | Tier 2 모델 ⊕ 어휘 |
| 주당 질책성 추궁 | |
| 제3자 노출 여부 | 단톡방 공개 질책은 고통을 가중 |
| 대상자의 시간외 응답 부담 | |
| **선택적 무응답 격차** | 동료 응답률 vs 대상자 응답률 — 폭언 없는 따돌림의 정량 신호 |

## 위험도와 조사 우선순위는 다르다

```
위험도(risk_score)   = 3요건 결합 (산술평균 ⊕ 기하평균)
                       → 괴롭힘 성립 가능성

우선순위(priority)   = 위험도 + 별건 법위반의 중대성
                       → 감독관이 먼저 볼 사건
```

기하평균을 절반 섞는 이유: 괴롭힘은 **3요건 동시 충족**이 성립 요건이므로,
한 요건이 0에 가까우면 나머지가 높아도 종합 점수가 오르면 안 됩니다.

우선순위를 따로 두는 이유: 임금체불(제43조)이나 신고자 보복(제76조의3 제6항)은
그 자체로 형사처벌 대상입니다. 괴롭힘 점수와 무관하게 먼저 볼 사건이 됩니다.

## 폐쇄형 RAG

검색 범위는 `data/law/` 안으로 **한정**됩니다. 외부 지식은 인용하지 않습니다.

| 파일 | 내용 | 상태 |
|------|------|------|
| `statutes.jsonl` | 근로기준법·산안법·산재보험법 조항 18건 | ⚠️ 원문 검증 필요 |
| `moel_manual.jsonl` | 고용노동부 매뉴얼 판단기준·행위유형 12건 | ⚠️ 원문 검증 필요 |
| `precedents.jsonl` | 판례 | ❌ **미수집** |

> **판례는 의도적으로 비워 두었습니다.** 사건번호를 추측으로 채우면
> 서비스 신뢰도가 통째로 무너집니다. 수집 절차는 `data/law/README_판례수집.md` 참조.
> 앱은 `verified: false` 인용에 ⚠️ 배지를 붙여 표시합니다.

**검색 백엔드**

| 우선순위 | 방식 | 조건 |
|----------|------|------|
| 1 | sentence-transformers + FAISS | 패키지 설치 시 |
| 2 | 문자 n-gram BM25 (순수 numpy) | 폴백 — 형태소 분석기 불필요 |

## 폴백 설계

시연 중 환경 문제로 앱이 죽는 일이 없도록, 모든 무거운 의존성에 폴백이 있습니다.

| 레이어 | 기본 | 폴백 | Tier 1 영향 |
|--------|------|------|-------------|
| 독성 분류 | KcELECTRA (`smilegate-ai/kor_unsmile`) | 어휘 사전 | 없음 |
| 법령 검색 | 임베딩 + FAISS | 문자 n-gram BM25 | 없음 |
| 리포트 문장 | LLM 보강 | 템플릿 | 없음 |

**Tier 1 정량 지표는 순수 pandas/numpy 연산**이므로 어떤 환경에서도 동일하게 나옵니다.

## 개인정보 보호

- 마스킹은 **분석 파이프라인 진입 전**에 수행 (`core/masking.py`)
- 실명 → `화자 A/B/C` **가명 치환** (삭제하지 않음 — 삭제하면 발화 독점률을 못 구함)
- 본문에 등장하는 화자 실명·호칭 변형도 같은 가명으로 치환해 재식별 차단
- 주민번호·연락처·이메일·계좌·카드·주소·사번·URL → 유형 태그
- 원본↔가명 매핑은 메모리에만 존재, 파일로 남기지 않음

## 한계 (숨기지 말 것)

- **위·변조 검증 없음.** 조작된 대화를 걸러내지 못합니다. 그래서 산출물은
  '증거'가 아니라 '정리된 자료'입니다. (확장 계획: 이미지 OCR·메타데이터 포렌식)
- **대화 기록에 한정.** 대면 발언, 업무 배경, 당사자 관계는 반영되지 않습니다.
- **판례 미적재.** 현재 인용은 법령·매뉴얼뿐입니다.
- **가해/피해 추정은 휴리스틱.** UI에서 수동 지정할 수 있어야 합니다. (미구현)
- **한국어 독성 모델의 직장 맥락 한계.** 공개 모델은 욕설에 강하지만
  "일머리가 없어" 같은 능력 비하에 약해, 어휘 사전과 앙상블합니다.

## 면책

본 서비스는 대화 로그의 통계적 분석 결과를 제공하며, 직장 내 괴롭힘의 성립 여부를
판정하지 않습니다. 사실관계의 진위 판별과 법적 판단은 근로감독관·노무사·변호사 등
권한 있는 전문가가 수행합니다. 생성되는 진정서는 **초안**이며 제출 전 전문가 검토를
권고합니다.

데모 대화 5종은 기능 검증을 위해 직접 작성한 **합성 데이터**이며 실제 인물·사건과
무관합니다.
